DynamiClinic: benchmark results

Does dynamic multi-agent switching beat one agent? Three arms on the same cases and model: single (one Primary Care Agent), dynamic (DynamiClinic: Meta-Controller triage, the care team only when needed, the Clinical Critic only when divergence exceeds τ 0.25) and static (the full care team plus Critic on every case). All runs are real, on OpenAI gpt-6-luna, 2026-10-27, unless marked otherwise.

Bottom lineNo benchmark shows the team beating one agent yet. On gpt-6-luna every arm is near its ceiling; on the weaker qwen3.5-4b there is headroom, but the single agent (68%) still leads DynamiClinic (60%) and the static team (62%), with overlapping intervals (Figure 1).

Since the proposal's three modes (f15) the adversarial debate runs on a third of MedQA, but accuracy stays inside the intervals and the dynamic arm uses more calls than the old always-on team (6.94 vs 6.00 per question). Before f14 it matched the full team with about 36% fewer calls.

Update 2026-10-28: uncertainty score and the proposal's three modes

Since f14 and f15 the Meta-Controller computes a Complexity Score C and an Uncertainty Score U (normalised entropy of a generalist's top-k differential) and picks the mode with one rule: U above τu is adversarial (Proponent, Clinical Critic as Opponent, Mediator); otherwise C at most 0.5 is hierarchical (Primary Care hub with up to 2 consults); otherwise collaborative (care team plus one mesh exchange round). τu is 0.15 for multiple choice and 0.59 for open-ended input, each the 75th percentile on these same vignettes: calibrated, not validated. Only the dynamic arm changed (single and static keep identical prompts), so only it was re-run.

  3. The mesh can talk a team out of a right answer: on syn-high-02 round 1's plurality was correct (C); after the exchange the Consensus Builder answered D, the safety gate blocked it twice, and the case ended with no answer.
  4. The mesh is often empty on MedQA: in 11 of 20 collaborative questions every specialist abstained in round 1 (no data for their modality), so the Consensus Builder answered alone.

Weaker base model: qwen3.5-4b, three arms, MedQA-50

gpt-6-luna is near its ceiling, so the same 50 questions were run with a 4B local model (LM Studio, qwen3-4b-2507) on 2026-10-28 to give the team room to help. Code with the three modes (2cf1567), one run per arm.

Figure 1, at the top of this page, plots the three arms.

  1. Headroom, but the team does not use it. Paired: single beats dynamic on 6 questions and loses on 2 (exact McNemar p = 0.29); single vs static 5 to 2 (p = 0.45). Not significant at n = 50, and the direction favours the single agent.
  2. The uncertainty threshold does not transfer across models. The 4B generalist is far less confident (median U 0.65), so 49 of 50 questions pass τu 0.15, calibrated on gpt-6-luna, and go adversarial: dynamic becomes the static team plus a Proponent and a sweep, at 8.32 calls per question.
  3. 2 errors on one question (LM Studio timeouts), counted as wrong. The Mediator skipped its verdict line in 11 of 49 debates.

Re-run with a threshold calibrated for qwen (0.81 multiple choice / 0.77 open-ended, the 75th percentile of qwen's own U on synthetic-24; MedQA-50 held out): dynamic 60% (30/50), the same accuracy, but the routing now spreads over the three modes (22 adversarial: 10 by uncertainty, 12 by the Conflict Detector; 21 collaborative; 7 hierarchical) at 7.44 calls per question instead of 8.32. The single agent still leads, 7 questions to 3 (exact McNemar p = 0.34).

What MedQA shows

  1. No accuracy benefit from the multi-agent arms. In Figure 3 the intervals overlap almost completely, and the single agent is one question ahead.
  2. Shared misses point at the model, not the orchestration. Three questions were missed by all three arms with the same wrong answer.
  3. The team once talked itself out of the right answer. On 0243, both team arms answered C where the single agent was right (A).
  4. The adversarial path never ran. Specialists almost always agreed (mean divergence 0.010), so the switch to the Clinical Critic, the core of the proposal, was not tested.
  5. The safety numbers mean little here. MedQA questions have no structured patient data and no marked unsafe options, so the safety gates had almost nothing to check.

Next steps

  • A larger or harder sample: more MedQA questions, or only the harder Step 2&3 questions, to narrow the intervals.
  • A weaker base model, so there is headroom for the team to help.
  • Safety-focused cases with structured patient data and marked unsafe options, so the safety gates and the adversarial path actually get exercised.

Reproduce from the repo root (needs OPENAI_API_KEY):

env -u PYTHONPATH -u VIRTUAL_ENV uv run python -m dynaclinic.eval.harness \
  --arms dynamic,single,static --dataset medqa --concurrency 4 \
  --context-policy shared_core --out docs/dynaclinic/results/<run-id>

Benchmarks are multiple choice; open-ended scenarios (any clinical text) are not benchmarked. See the fact check for real runs of those.
